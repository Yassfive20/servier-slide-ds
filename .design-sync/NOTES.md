# Sync notes

## Known render warns (triaged, safe to ignore on re-sync)
- **`Icon` — `[RENDER_THIN]`, "mounts have no text and paint nothing"**: false positive. `Icon` renders pure SVG glyphs with no text nodes, so the render-check's text-content heuristic always trips for it even when the icons visually paint correctly (confirmed via the rendered sheet — `icons__Icon.png` shows all 11 icons across 3 stories rendering cleanly, styled and legible). Not a real defect; expected to recur every sync.

## Repo-specific setup
- No Storybook — package shape. Build: `npm run build` (esbuild + tsc) from repo root, before running the converter.
- Converter run: `node .ds-sync/package-build.mjs --config .design-sync/config.json --node-modules ./node_modules --entry ./dist/index.js --out ./ds-bundle`.
- Render check / capture browser: no Playwright Chromium download needed — point at the system Chrome instead: `DS_CHROMIUM_PATH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"` env var on both `package-validate.mjs` and `package-capture.mjs`.
- Fonts: Poppins (the brand's actual corporate/digital typeface per the charte graphique) is shipped as data-URI `@font-face` rules embedded directly in `dist/styles.css` (see `src/fonts/poppins.css`, pulled in via `build.mjs`'s `loader: {".woff2": "dataurl"}`). Century Gothic (the brand's office-document typeface) is NOT shipped — it's proprietary/not freely redistributable, and Poppins is the correct substitute for web/digital use per the brand's own typeface split. No `[FONT_MISSING]` should fire; if it does, the font CSS import chain broke — check `src/styles.css` still `@import`s `./fonts/poppins.css`.

## Config: viewport overrides are load-bearing
Every one of the 32 `src/slides/*.tsx` components AND the `SlideFrame` primitive (`src/primitives/SlideFrame.tsx`) render a fixed 1280x720 canvas. The capture tool's default viewport (900x700) clips them. `.design-sync/config.json`'s `overrides` block sets `{"cardMode": "column", "viewport": "1280x720"}` for all 33 of these — **any new slide-shaped component (or a new primitive built on `SlideFrame`) needs the same override added**, or its preview cards will render clipped/wrong-aspect-ratio. This bit us once already for `SlideFrame` itself (missed on the first pass, added after a subagent caught it) — check first before assuming a new component is exempt.

## Real bugs found + fixed during the first sync (all in shared primitives, so worth knowing before extending them)
1. **`annulusPath` (`src/primitives/arc.ts`)**: a 360° sweep produced a degenerate SVG arc (start/end points coincide → invisible path). Fixed by clamping any ≥360° span to 359.99°. Affects `PercentageRing` (`mode="full"`) and `SegmentedRing` (`mode="full"`).
2. **`SegmentedRing` label collision + clipping (`src/primitives/RingChart.tsx`)**: originally labels sat only 26px outside the ring, which (a) let same-colored labels visually collide with their own wedge (e.g. a navy caption over a navy wedge — invisible where they overlapped, looked like truncated text) and (b) — after widening the clearance to fix (a) — could push a label near the top/bottom of the canvas past the container's edge (clipped or fully invisible, seen with a segment whose midpoint angle lands near 0°/top). Fixed by widening clearance to 50px *and* padding the container/shifting the draw origin so labels near the top/bottom always have room, with padding sized down when `showLabels={false}` (avoids wasted vertical space on `DonutLegendChartSlide`, which doesn't show outer labels).
3. **`PercentageRing` half-mode label contrast (`src/primitives/RingChart.tsx`)**: the center label's text color is always navy, but in half mode it sits low enough to underlap the ring's own band — low/no contrast whenever the ring color is also navy (the default). Fixed by giving the half-mode label a white pill backdrop (`background: var(--sv-blanc)`, rounded), matching how the same overlap reads fine in the brand's original PPT ("Percentage slide") reference art. Full-mode's center label sits in the true donut hole (never overlaps), so it's untouched.
4. **`RadialIconWheelSlide` title/ring overlap (`src/slides/RadialIconWheelSlide.tsx`)**: the title was nested inside the ring's hollow at a fixed `top:340`, which collided with the top-center item's caption (captions for near-top items hang up to 90px above their icon). Restructured to a conventional heading-above-diagram layout (title at `top:50`, ring pushed down to `top:150`, ring `size` reduced 620→520) — trades a bit of the brand's nested-composition look for layout robustness across arbitrary item counts/label lengths.
5. **`LineChartSlide` / `BarChartSlide` capture-timing (`src/slides/*.tsx`)**: Recharts' default draw-in animation wasn't finished when the headless capture screenshot fired, so `<Line>` charts visibly stopped partway across the x-axis (reproduced deterministically twice). Fixed by adding `isAnimationActive={false}` to both `<Line>` and `<Bar>` (the latter hadn't visibly failed yet but has the same risk).

## Design choices flagged during preview authoring, not changed
- **`SectionDividerSlide`** has a lot of open white space on the right two-thirds of the canvas by design (text block left-anchored, nothing fills the remaining ~380px). Matches source layout intentionally — sparse "chapter break" look — but worth a deliberate look if a denser composition is ever wanted.
- Placeholder imagery for previews (`picsum.photos/id/<n>/...`) is subject-matter-random (landed on dogs, buildings, a jellyfish) — fine for a component-library preview per the authoring brief, but not pharma-themed. A future pass wanting on-brand stock photography would need a different source.

## Re-sync risks (what could go stale)
- All 47 authored previews (`.design-sync/previews/*.tsx`) use invented-but-realistic pharma market-access consulting content (Q3 reviews, launch readiness, payer coverage, therapeutic-area splits, etc.) — none of it is pulled from real client data, there's no `examples/`/docs source in this repo to curate from. If real reference decks or content guidelines become available later, previews should be re-authored from those instead.
- `SegmentedRing`'s wide-first-segment label placement was flagged as marginal in one batch (a very wide, ≥~30%, first segment with a long label could still crowd its own label) — the clearance/padding fix (bug #2 above) should have resolved this as a side effect, but wasn't explicitly re-tested with an adversarial wide-first-segment case. Worth a spot-check if `SegmentedRingChartSlide` ever renders oddly with real data.
- The brand's actual logo is NOT shipped — `src/primitives/Logo.tsx` is a styled-text approximation (Poppins bold italic "SERVIER" + a small star glyph), not the real vector lockup. Swap it for the real SVG when available; every slide component renders this approximation.
- Pictogram icons (`src/icons/Icon.tsx`) are simplified line-art approximations of the brand's pictogram library, hand-drawn from a PDF reference, not traced from the original vector source.
- Build assumes network access was available once (to fetch Poppins from Google's public font repo) — the resulting woff2s are committed as data URIs in the built `dist/styles.css`, so a re-sync doesn't need network access again, but if `src/fonts/*.woff2` source files are ever regenerated, that step does.
